\reviewersection{Reviewer 1, Comment 1 (R1.1)}
\begin{reviewercomment}
Segmentation and classification results are largely reported at the image level. The authors should clarify patient- and examination-level splits, cross-dataset deduplication, and whether multiple frames or views from the same patient appear across splits. Patient-level re-analysis and cluster-aware confidence intervals would strengthen confidence in the reported performance.
\end{reviewercomment}
\begin{authorresponse}
\begin{itemize}
\item We thank the reviewer for this important point. We revised our statistical reporting as follows.
\item Independence and near-duplicates. We screened \textbf{pairwise across source cohorts} (TN3K, TN5K, ThyroidXL, DDTI, PKTN, ZJH-8K, etc.) using dHash (Hamming ≤ 5; \textbf{Table R1} at the end of this letter). For the ZJH–TN3K question (R2.4): TN3K (official train+val+test) vs ZJH-8K shows \textbf{1156} H=0 pairs; TN3K \textbf{official test} vs ZJH-8K shows \textbf{2} H=0 pairs. Cluster definitions. Where patient IDs are available (ZJH-8K, ThyroidXL), we use patient-level clusters; for cohorts without IDs, we use one image per cluster. Bootstrap CIs (1000 resamples, seed 42) are cluster-aware.
\item Patient-level classification. For ZJH-8K and ThyroidXL we report patient-level AUROC/AUPRC after aggregating image probabilities (arithmetic mean within patient).
\item Cluster-bootstrap confidence intervals. We recomputed 95\% CIs using 1000 cluster bootstrap resamples (seed 42). \textbf{Table S4} (benign–malignant classification: seven methods × five test cohorts) and \textbf{Table S3} (nodule segmentation: five methods × seven test cohorts; Dice and HD95) are in \textbf{Tables R2–R4} at the end of this letter. DDTI classification uses \textbf{n=349}; segmentation \textbf{DDTI} uses \textbf{637} images.
\end{itemize}
\textbf{Supporting material:} See \textbf{Table R1} (dHash near-duplicate screening), \textbf{Tables R2–R3} (Supplementary Table S4, AUROC/AUPRC), and \textbf{Table R4} (Supplementary Table S3, segmentation Dice/HD95) at the end of this letter.

\reviewersection{Reviewer 2, Comment 2 (R2.2)}
\begin{reviewercomment}
Many analyses are reported at the image level although the same patient, examination, or nodule may have multiple images (e.g., ZJH-8K contains 7,958 images from 1,149 patients). Treating correlated images as independent may yield overly narrow confidence intervals. The authors should use patient- or examination-level bootstrap resampling and report patient-level performance for clinically meaningful classification tasks.
\end{reviewercomment}
\begin{authorresponse}
\begin{itemize}
\item We agree that treating multiple images from the same patient or examination as independent can yield anti-conservatively narrow confidence intervals and misaligns with clinical decision units.
\item \textbf{Statistical protocol (Methods):} Where reproducible \textbf{patient IDs} exist (ZJH-8K, ThyroidXL), bootstrap resamples \textbf{patient clusters} with replacement (1000 resamples, seed 42) before expanding to images; cohorts without IDs (e.g., TN3K, TN5K, DDTI) use \textbf{one image per cluster}. All \textbf{95\% CIs} in \textbf{Tables S3–S5} are reported under this cluster-bootstrap convention.
\item \textbf{Which cohorts change:} For \textbf{TN3K, TN5K, DDTI}, one image per cluster implies cluster-bootstrap \textbf{95\% CIs match per-image bootstrap} (point estimates unchanged). \textbf{Only ZJH-8K and ThyroidXL} show \textbf{slightly wider} image-level CIs under cluster resampling, plus \textbf{patient-level} classification and segmentation (\textbf{Tables R9} and \textbf{R10} at the end of this letter); other benign–malignant cohorts are in \textbf{Tables R2–R3} at the end of this letter.
\item \textbf{ZJH clustering (manuscript-wide):} We use one \textbf{patient-level cluster} rule for ZJH images (name/\texttt{patient\_id} mapping; malignant-task development manifests share the same patient-ID construction). \textbf{1146} clusters on the full test set versus fewer clusters in the malignant development pool reflect \textbf{different image subsets}, not different clustering keys.
\item \textbf{Benign–malignant classification (patient-level supplement):} For ZJH-8K and ThyroidXL we \textbf{arithmetically average} image-level malignancy probabilities within patient, assign patient labels by the \textbf{within-patient max} over images, and report patient-level AUROC/AUPRC with cluster-bootstrap CIs (\textbf{Tables R9} and \textbf{R10} at the end of this letter), in addition to image-level Table S4.
\item \textbf{Segmentation:} Image-level Dice remains per-image; the revised full \textbf{Table S3} (all baselines × seven cohorts, Dice/HD95 layout) is \textbf{Table R4} at the end of this letter; \textbf{mean within-patient Dice} for ZJH-8K and ThyroidXL is \textbf{Table R10} at the end of this letter.
\item \textbf{Malignant subtyping (LNM, FTC/PTC):} \textbf{Table S5a} reports LymphUs Center 2 / FangDai \textbf{external} tests; \textbf{Table S5b} reports development five-fold \textbf{OOF} for the three expert systems, separate from image-level bootstrap summaries where applicable.
\item \textbf{ZJH-8K patient count:} Reproducible ID clustering yields \textbf{1146} patients (\textbf{7958} images); the \textbf{1149} cases cited by the reviewer reflect the cohort’s original registration field---we clarify mapping and exclusions in Methods.
\end{itemize}
\textbf{Supporting material:} Full \textbf{Tables S3/S4} are \textbf{Tables R2–R4}; patient-level ZJH-8K / ThyroidXL results are \textbf{Tables R9} and \textbf{R10} at the end of this letter.

\end{itemize}
\begin{promptverbatim}
You are a segmentation model selection agent. Choose the best mask from the JSON metrics in the user message.
Do not output chain-of-thought, Markdown, or any text outside JSON. The first character must be { and the last must be }.
Output a single line of JSON with "selected_model", "confidence" (0–1), and "reasoning" (fixed to "-"). Example: {"selected_model":"<name>", "confidence":0.9, "reasoning":"-"}

\end{promptverbatim}
\begin{itemize}
\item \textbf{Optional system append --- independent classifiers agree} (classification anchor; example «malignant»):
\end{itemize}
\begin{promptverbatim}

[Classification anchor (key signal)]
Three independent classifiers (no mask required) unanimously label this image as malignant.
Use this anchor to judge each segmentation:
- Radiomics-judge class contradicting the anchor → the mask may cover the wrong ROI → substantially lower trust.
- Mask consistent with the anchor → bonus.
- If all masks’ radiomics classes contradict the anchor → select the mask with highest confidence and explain why.
\end{promptverbatim}
\begin{itemize}
\item \textbf{Optional system append --- independent classifiers disagree} (no classification anchor):
\end{itemize}
\begin{promptverbatim}

[No classification anchor]
Independent classifiers disagree; no consensus.
Whole-image features are ambiguous. Prioritize:
1. Internal consistency of radiomics judges (similar class direction across masks → more trustworthy)
2. Morphologic plausibility (circularity 0.6–0.9, single connected component)
3. Device match and historical performance
\end{promptverbatim}
\begin{itemize}
\item \textbf{User template}: optional disagreement summary + device/data lines +
\end{itemize}

\item \textbf{Output JSON}: \texttt{\{"selected\_model": "<name>", "confidence": 0.0–1.0, "reasoning": "..."\}}
