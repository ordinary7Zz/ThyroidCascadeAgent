## 2. 核心结论（可写入回复信的主线）

1. **对比用的监督分割模型**（TransUNet、MedSAM2 结节、MedSegX 结节、UltraFedFM 结节）均在论文意义上的 **segmentation dataset4**（TN3K + ThyroidXL + PKTN + TN5K 堆叠）上完成甲状腺域微调，**不是**在甲状腺数据上零样本或仅用公开权重直接测试。

2. **对比用的监督分类模型**（ResNet-50、RepViT、LSNet、UltraFedFM 分类、BiomedCLIP、MedSigLIP 微调版）均在 **classification dataset3**（TN3K + ThyroidXL + TN5K 堆叠）上训练；路径多为 `dataset_3_cls`，ResNet-50 与 ThyroidXAgent DINO multitask 使用同堆叠的 `dataset_3`（images + masks + JSON，训练图像数与 `dataset_3_cls` 一致：**15109**）。

3. **ThyroidXAgent** 满堆叠结果同样基于上述开发堆叠（分割 DINO 专家 + 分类 multitask）；此外为 Table S6 在 **dataset1→dataset4（分割）**、**dataset1→dataset3（分类）** 上做了逐级叠加消融——**对比基线没有这套多级消融，只有满堆叠一版**。

4. **因此可回应 R2.14 的主要关切：** 主要 S3/S4 比较不是「Agent 多队列训练 vs 基线 off-the-shelf」，而是「在同一开发堆叠上微调的不同架构 + Agent 路由/集成」。公平性需在补充表中写清 **预训练来源 + 甲状腺开发集 + 推理输入**，而非默认再训。

5. **未纳入本结论的模型：** `Classification_Agent/vllms/` 下 GPT-5、Gemini、MedGemma、Qwen3-VL 等——**不在相同 stacked 数据上端到端训练**；若仍出现在 S4，须在补充表中单独标为 **零样本 / API + 固定 prompt**，与监督基线分块叙述。

6. **患者粒度：** 当前开发划分均为 **图像级** train/test，**不能**在 B10 回复中声称 patient-level 互斥训练；patient 级问题由 B1/B2（R1.1、R2.2）单独回应。

数据根目录：`/mnt/wangbd8/workspace/DataSets/ThyroidAgent/`

| 代号 | 路径 | 堆叠队列 | 用途 |
|------|------|----------|------|
